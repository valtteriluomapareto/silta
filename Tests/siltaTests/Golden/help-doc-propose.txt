OVERVIEW: Submit a complete document proposal.

Use -F for complete UTF-8 Markdown and -m to explain the proposal.
New docs need --title and --about; accepted metadata otherwise stays.
Submissions remain pending. Read with doc show or the human inbox.
Read editing rules with silta guide docs.
Example: silta doc propose api -F api.md -m Clarify --title API --about app:api

USAGE: silta doc propose [--ws <ws>] [--approved <approved>] [--json] [--quiet] [--verbose] <slug> [-F <file>] [-m <why>] [--title <title>] [--about <about> ...] [--base <base>] [--task <task>]

ARGUMENTS:
  <slug>                  Doc slug or doc:slug, without a revision.

GLOBAL OPTIONS:
  --ws <ws>               Use this workspace; default is inferred or saved.
  --approved <approved>   The human's words approving this command in chat;
                          default is none.
  --json                  Print the JSON envelope on stdout; default is text.
  --quiet                 Hide success text; warnings and errors still show.
  --verbose               Mirror command diagnostics to stderr.

OPTIONS:
  -F <file>               Read complete UTF-8 Markdown from a file, or - for
                          stdin.
  -m <why>                Explain why this knowledge should be shared.
  --title <title>         One line of at most 120 characters; required for a
                          new doc.
  --about <about>         Canonical map ref; repeat to replace the complete
                          set; required for a new doc.
  --base <base>           Accepted owned revision used as the proposal's
                          baseline.
  --task <task>           Owned source task; otherwise use the session's sole
                          live claim.
  --version               Show the version.
  -h, --help              Show help information.
